## 2026-08-11 15:44 彻底修复：IncompleteRead 崩溃 + pull 自回滚

- **IncompleteRead 崩溃**：拉取 `lessons.md`（346KB）时频繁报 `IncompleteRead(474xxx bytes read, xxxx more expected)` 或 `[WinError 10054] 远程主机强迫关闭了一个现有的连接`（ConnectionResetError），直接导致脚本崩溃/秒退。
  - 根因：`api_request` 没有重试，单次网络抖动即抛异常 → `main` 的 `except Exception` 捕获但 repo 已中断；加上 python `-u` 之前缓冲未 flush，用户只看到窗口秒退。
  - 修复：
    1. `api_request` 增加 3 次重试循环，对 `IncompleteRead`、`ConnectionResetError`（`OSError`）、`URLError`、`HTTPException`、5xx 均自动重试，退避间隔 `2*attempt` 秒。4xx（401 等）不重试直接抛。
    2. bat 中的 python 调用加上 `-u`（无缓冲），崩溃日志不再丢失。
  - 验证：`pull` 过程中出现 `[重试 1/3] 网络抖动: IncompleteRead(...)` 后自动恢复，`lessons.md` 正常下载，三仓库 `pull` 全部完成 exit=0。

- **修复被 pull 回滚的隐蔽 bug**：编辑好的 `git-sync.py` 反复「修完消失」。
  - 根因：`do_pull` 的 EXTRA_SYNC 包含 `git-sync.py`（双向同步工具脚本本身）。每次 `pull` 下载仓库旧版 → 用 `shutil.copy2` 把仓库旧版覆盖到运行母本 → 修改瞬间被回滚。
