### fba 修复（克隆法，因 init+fetch 在 Claw 嵌套目录下写不了 ref）
- 根因：`football-betting-analysis/.git` 是**损坏的独立仓**（显式 `--git-dir` 也报 not a git repository），故 `git -C fba` 回退到 Claw 仓
- Claw 仓 `.gitignore` 完全忽略 `football-betting-analysis/` → 修成独立仓**零爆破半径**
- 修法：备份损坏.git → Claw 外 `git clone fba.git` 到 D:/fba_clone_tmp（refs 正常落盘，origin/main=5a2804b）→ 把克隆的 .git 换入 fba → `reset --hard origin/main` → 校验 pull=Already up to date
- ⚠️ **坑**：在 Claw 仓嵌套子目录里 `git init`+`git fetch` → fetch 报"已建 origin/main"但 ref 不落盘（refs/remotes/origin 目录不存在、packed-refs 不存在、for-each-ref 空），必须用"Claw 外干净 clone 再换 .git"绕过
- 本地 fba vs 老二版：本地独有文件=0、仅老二版有6个(v170/v172报告+sync_ssh.py)、内容不同24个 → 以老二 5a2804b 为 canonical 对齐，无本地独有内容丢失

### pipeline-v8 同病 + 修正我的 commit+push 建议
- 同样：独立 `.git` 损坏，`git -C` 回退 Claw；我上一条 `git commit` 因 .git 损坏没真正落盘（Claw log 仍停在 8fb5905，无坏提交）
- ⚠️ **关键修正**：`git status --short` 显示 30+ "M" 多为 **CRLF 行尾归一化假差异**（一堆 `LF will be replaced by CRLF` 警告）；真实内容差异（`diff origin/main --stat`）只有 **9 个文件且全是删除**（我本地落后老二 9 个文件），**无新增** → 我本地无任何老二没有的独特内容
- 故 pipeline-v8 不能 commit+push（会删老二仓库文件），正确动作=同 fba 对齐：换入克隆好 .git + `reset --hard origin/main`(=86a1ae1 老二"merge xieyu hub state")，diff 归空，pull=up to date
- match-analysis 经核查早已干净+synced（"脏改动"是已提交的 sync: 提交，log 可见），无需处理

### 复用教训（重要）
1. 嵌套在父 git 仓下的子目录独立仓若 `.git` 损坏，`git -C 子目录` 会静默回退父仓；用"父仓外干净 clone → 换入 .git"修复，勿用 init+fetch
2. `git status` 的 M 可能因 autocrlf 假阳性；以 `git diff origin/main --stat` 判真实内容差异
3. 双机同步中"本地脏改动"未必是真工作——先 `diff origin/main` 确认有无独有内容，再决定 commit+push 还是对齐远端
